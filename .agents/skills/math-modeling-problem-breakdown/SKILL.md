# 数模赛题拆解（Math Modeling Problem Breakdown）

## 这个 Skill 解决什么问题

数模比赛真正卡住人的，往往不是写不出代码，而是**开场就没想清楚**：题目要的到底是预测还是优化？附件数据够不够支撑结论？几个候选模型为什么选这个不选那个？

本 Skill 把"读题"这一步流程化：把赛题原文变成一份可以直接开工的方案，并对每个结论标注它需要什么数据支撑。产出是**方案**，不是论文，也不是最终答案。

## 何时使用

- 用户贴出赛题原文、截图或附件说明，问"这题怎么做"
- 用户已有思路，想让方案被挑毛病
- 用户要为一个具体小问选模型（如"这道预测题用 ARIMA 还是 LSTM"）

不适用：纯代码调试（此时只回答问题本身，不要套模板）、论文润色（本 Skill 只管建模方案）。

## 执行步骤

### 第 1 步：切分任务

- 找出题目的**每一小问**，逐条编号（问题一、问题二……）。一小问通常对应一个独立产出，不要合并。
- 对每一问，提取三项：**输入**（给了什么数据或条件）、**输出**（要交什么）、**评价口径**（题目用什么标准衡量好坏，如误差、成本、时间）。
- 题目里的"附件 1、附件 2"要单独列一张清单：文件名、字段、行数、时间跨度、单位。没看到数据就先标"待核实"，**不要假装知道字段**。

### 第 2 步：问题重述（每问 3–5 句）

把题目语言改写成建模语言，句式固定：

> 在（假设条件）下，用（可用数据）估计或优化（目标量），使得（约束）成立，并以（指标）评价。

改写后必须能回答："这题的输出是一个数、一条曲线、一个方案，还是一段分类标签？"如果答不上来，说明还没读懂，回到第 1 步。

### 第 3 步：变量与假设

- **变量表**：决策变量、状态变量、观测量、参数，四类分开列，写清符号、含义、单位、取值范围。
- **假设表**：每条假设写三列——假设内容、为什么需要它（不用这个假设模型就闭不了）、它可能带来什么偏差。
- 假设数量控制在 5–8 条。写不出"可能偏差"的假设，多半是废话，删掉。

### 第 4 步：候选模型对比（每问 2–3 个）

每个候选给出：

| 字段 | 要求 |
|---|---|
| 方法 | 具体到模型族，不写"机器学习"这种空话 |
| 适用条件 | 数据量、分布假设、是否要求平稳或独立 |
| 数据要求 | 需要哪些字段，当前附件是否满足 |
| 可解释性 | 高、中、低，评委能不能看懂 |
| 实现难度 | 有无成熟库，调参成本 |
| 风险 | 最可能失败的地方 |

然后给**明确推荐**和一个备选，并写一句"为什么不选另一个"。不要罗列一堆方法让用户自己挑——那不是指导。

### 第 5 步：数据体检（决定结论可信度的关键）

逐项检查并给出判断，而不是罗列：

1. **样本量**：够不够支撑该方法的参数个数（经验法则：每个待估参数至少 10–20 个观测）
2. **缺失与异常**：缺失比例、异常值处理方式（删除、插补、截尾），以及它对结论方向的影响
3. **量纲与尺度**：是否需要标准化，为什么
4. **时间结构**：有无趋势、季节、自相关，决定能不能直接套独立同分布假设
5. **共线性**：变量间相关性，决定回归系数能不能解释

**必须指出"这组数据支撑不了什么结论"**。样本量小就说小，不要用复杂模型掩盖。

### 第 6 步：求解步骤

写成可执行的顺序，每一步标明：

- 用什么工具（Python 生态为主：pandas、numpy、scipy、statsmodels、scikit-learn）
- 输入是什么、输出是什么
- 这一步做完应该看到什么现象，看到什么说明走错了

关键步骤要提示常见坑，例如：时间序列先做平稳性检验再定阶；分类任务先看类别是否失衡再选评价指标（失衡时准确率会骗人）。

### 第 7 步：验证方案

每问至少给两种验证，缺一不可：

1. **内部验证**：残差诊断、交叉验证、留出集，或与基线模型对比（基线必须有，否则无法证明复杂模型有价值）
2. **敏感性验证**：改关键假设或参数 ±10%，结论是否翻转

再补一条**诚实边界**：模型在什么条件下失效（外推范围、数据分布变化、样本外场景）。

### 第 8 步：论文图表清单

列出需要的图与表，每项写清"这张图要证明什么"。评委看图的时间远多于看公式。

- 数据概览图（分布、趋势）
- 模型拟合或方案对比图（要有基线对照）
- 敏感性分析图（参数变化下的结论稳定性）
- 结果汇总表（各问结论、关键指标、置信区间）

## 输出格式

```
## 一、题目拆解
（小问清单表：编号 / 输入 / 输出 / 评价口径）

## 二、问题重述与假设
（每问的建模语言重述 + 假设表）

## 三、模型方案
（每问：候选对比表 + 推荐方案 + 不选另一个的理由）

## 四、数据体检
（5 项检查结论 + "本数据支撑不了的结论"）

## 五、求解步骤
（编号步骤，含工具与中间检查点）

## 六、验证与风险
（内部验证 + 敏感性 + 失效条件）

## 七、图表清单
```

## 硬性要求

1. **不编数据**。附件没给就写"待核实"，不猜字段名、不编数值。
2. **不编文献**。需要引用方法出处时，只写公认的经典方法名，不构造作者、年份、期刊。
3. **不下无依据的结论**。样本量小、相关性弱时，明确写"不显著"或"证据不足"，并给出样本量或检验统计量作为依据。
4. **区分假设与事实**。凡是"我假设"的内容都必须显式标注，不能混进结论。
5. **不确定就写不确定**，并说明需要什么信息才能确定。

## 使用示例

**示例 1：完整拆题**

> 用户：这是今年校赛 A 题（贴图），三问，附件给了两年的逐日客流数据。帮我拆一下。

输出：先列三问的输入、输出、评价口径 → 指出第二问要预测、第三问要优化，两者评价标准不同，不能共用一套指标 → 数据体检指出样本只有 730 天、做神经网络参数太多 → 推荐第一问用描述统计加分季节分解，第二问用 SARIMA 作基线再对比梯度提升 → 给出验证方案与图表清单。

**示例 2：单点选型**

> 用户：这道题让我预测未来 30 天销量，数据只有 400 条，用 LSTM 行不行？

输出：直接回答"不建议"并给理由（参数数量与样本量不匹配、易过拟合、外推能力弱），给基线方案（季节分解加线性趋势，或梯度提升加滞后特征），说明如何用滚动验证公平比较两者，并指出若一定要用神经网络，需要满足什么条件才站得住。

## 常见反模式

- 一上来就写公式和代码，跳过错题与数据检查
- 把三小问写成一个大模型，导致评价口径混乱
- 只给一个模型，没有基线和备选，无法证明选择合理
- 用"数据量足够""精度很高"这类没有数字支撑的话下结论
- 敏感性分析写成"结果比较稳定"却不给具体参数和变化幅度
